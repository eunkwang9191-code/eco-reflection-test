사전·사후 자동 비교 기능 설치 (v4)

1. 기존 Google Sheets 문서 열기 (교사만 접근 가능하게 비공개 유지).
2. 확장 프로그램 > Apps Script에서 GoogleAppsScript_Code.gs 전체 내용을 붙여넣고 저장.
3. 이미 Apps Script를 배포했다면 '배포 > 배포 관리 > 수정 > 새 버전'으로 재배포. 처음이라면 '새 배포 > 웹 앱', 실행 사용자 '나', 접근 권한 '모든 사용자'.
4. 웹 앱 /exec URL을 복사하여 index.html의 PASTE_YOUR_APPS_SCRIPT_WEB_APP_URL_HERE를 대체.
5. GitHub 저장소 최상위에 수정한 index.html, sw.js를 업로드/덮어쓰기하고 Commit.
6. 시트의 '환경 검사 관리 > 전후 비교·통계 갱신' 메뉴가 보이지 않으면 Sheets를 새로고침.
7. 샘플 코드 TEST123으로 사전/사후 검사 각각 1번 제출 → 설문응답 탭에서 각 기록 확인 → 전후 비교·통계 갱신 실행.
8. 생성된 전후비교, 종합통계 탭에서 점수변화·레벨변화·영역별 변화·대응표본 t검정 참고값 확인.
9. 시험용 데이터 삭제 후 실제 운영. 삭제할 때는 설문응답의 샘플행을 지우고 통계를 다시 갱신.

운영상 중요사항
- 익명 영문숫자 코드(5~16자리)를 사전/사후 동일하게 사용. 이름은 선택이며 코드 공유/분실·중복 방지에 대한 안내 필요.
- 사전·사후 문항, 점수 방식, 레벨 구간은 동일하게 유지해야 비교 가능.
- 일관성 70 이하 '야곱'은 거짓말 판정이 아니며, 분석 시 별도 표시한다.
- 비교 표에서 같은 코드·같은 시점의 중복 응답은 마지막 제출 기록만 사용한다. 반복 제출 방지는 별도 구현 필요.
- 웹페이지는 별도 데이터를 저장하지 않으며 Google Apps Script / Sheets가 저장을 맡는다.
- no-cors 요청은 브라우저가 성공 응답을 판별하지 못하므로 실제 시트에 들어왔는지 확인 필수.
- 접속이 공개된 저장 API에는 허위 응답 가능성이 있다. 학교 조사 시 과다·중복 제출 모니터링 필요.
- 이름/별명, 응답 내용은 개인정보가 될 수 있다. 수집 목적, 보관기간, 접근권한, 삭제 절차를 안내하고 불필요한 본명은 수집하지 말 것.
- 20개 자기보고 문항은 공인 검사가 아니다. 유의확률이 낮아도 프로젝트만의 인과적 성과는 입증되지 않는다. 쓰레기통 현장 관찰과 함께 해석할 것.
